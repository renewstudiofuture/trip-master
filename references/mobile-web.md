# 手机网页与本地操作

五个固定内容模块：行程、景点、购物、餐饮、贴士。行程包含按天路线、用户提供的交通住宿与规划预算；贴士包含可勾选事项。记账、调整、分享、换皮肤作为工具入口，不增加内容模块。

模板默认为包豪斯纸白、黑字、红黄蓝、几何编号，手机优先；可切换内置纸境拼贴，详见 [视觉风格](visual-style.md)。首页使用目的地封面，地点卡片保留实景图片。文字简洁，但日期、站点、预订状态和关键衔接不能精简掉。默认不改模板，不为每次旅行开发新前端。

`build_mobile_html.py trip.json index.html` 输出内嵌 CSS/JS/数据的 HTML；image_asset 图片随构建复制到 assets/，发布需包含这些文件。基础行程不依赖 JS，个人操作需要 JS。外部图片、导航、来源链接需要网络；图片加载失败显示说明。不能声称地图或图片已离线缓存。

问卷：`build_intake.py questionnaire.html --brief brief.json`，只读取允许的五组字段，已知值覆盖本机草稿。无需先装额外运行环境即可打开 assets/questionnaire.html；无脚本环境可直接用文字需求。问卷只生成可复制需求，并不会自动发给 Agent。

账本：币种独立汇总，默认旅行当地日期；金额通过定点解析，JPY/KRW无小数。支持编辑、删除、导出/导入，带行程 ID 的个人记录包。只记录实际支出；预订不会自动计入。预算有 total/per_person 范围，人数未知不推导人均预算总额。不做汇率、分摊、还款、云同步。

个人数据存储键使用 trip_id，不能包括 revision。任务指纹改变会提示重新确认，不自动把旧勾选当作新任务已处理。删除日程不得删除历史支出。数据损坏停止覆盖；存储失败保留本页内容并给导出；不能保证无痕或清理后仍保留。重复导入按稳定账目ID去重，冲突整批拒绝，不选后写覆盖。

本地行程编辑支持增加、修改、删除、跨天移动、同日排序；保存立即重绘逐日行程。使用独立 `trip-master:<trip_id>:itinerary` 存储，以 base_revision 检查版本；异版记录不应用也不覆盖，允许导出并由助手合并，或用户明确恢复原版。锁定项目不能在页面编辑。个人行程导入须核验ID、日期、版本和锁定内容；公共分享链接不共享个人调整。独立的“需要助手重新规划”入口才复制内容回聊天。

预算总额和同币种账目实时关联，主页与记账区复用同一汇总；展示剩余或超额及比例。人均预算仅在人数已知时折算；外币单列。紧凑账目行以说明、金额为主，日期/分类次之，操作折叠。


分享 HTTPS 页面可用系统分享，缺少能力回退复制地址。本地文件明确尚未发布。微信可达性须实测；更换域名／设备用个人记录包导入，不宣称自动同步。数据导出包含个人消费信息，不随公开攻略上传。

从行程点“看景点介绍”保存来源活动ID及视口位置，展示悬浮“返回刚才行程”；返回后隐藏，按来源元素的新位置恢复，避免图片加载造成错位。图片署名/许可折叠显示，来源状态保留在数据中，不在正文反复输出“公开核实”。
