# 手机交互版与微信打开方式

用户需要手机点击日期跳转、微信阅读，或反馈PDF内链失效时，交付响应式HTML作为交互主版本，PDF仅用于离线阅读／打印。不因PDF存在链接注释就声称微信阅读器支持跳转。

## 设计与生成

可用时应用frontend-design。当前用户偏好：包豪斯风格，纸白底、黑字、红黄蓝几何色块、直角边框、清晰网格与字号对比；信息精简，几何元素服务层级，不遮挡行程。沿用圆周旅迹的按天查看、交通和住宿分开组织的逻辑。

默认结构：总览日期列表 → 日期导航 → 当日顺序卡片；底部直达行程、住宿、预算、待办。非总览页收起装饰性封面，让当天信息优先显示。关键未核实状态保持可见，不折叠到用户看不到的地方。

```bash
python scripts/build_mobile_html.py outputs/trip-cards.json outputs/mobile/index.html
```

沿用pdf-design.md中的卡片JSON；补充可选`mobile_title`、`intro`、`status`，控制网页标题、短引言、资料日期与证据说明。当前模板使用overview、stay、budget、todo、sources五个栏目ID，加day开头的日期ID；这些栏目均应提供。总览卡片需有有效target。模板在`assets/mobile.html`，无远程字体、脚本、图片依赖。无需登录或调用浏览器生成；此JSON不是第三方App导入格式。

HTML包括原生锚点、hash日期切换、详情折叠、底部栏目、可见焦点、减少动画偏好与无JS展开回退。点击来源使用真实HTTP(S)链接。不要模拟地图、订票、多人同步等未实现功能。

## 文件与链接必须区分

- 单文件HTML：可下载后交给支持HTML的浏览器打开；不能保证微信附件预览执行页面交互。
- localhost或本机文件路径：仅是当前电脑预览，不是手机公网链接。
- 微信内直接打开：需要实际托管的HTTP(S)网页地址；优先HTTPS。未经发布不得伪造地址、把本地预览当分享链接或承诺微信已实测通过。
- 若用户明确要求发布／分享网页，使用可用且获授权的托管流程；先核对发布内容是否包括姓名、证件、订单号和带签名URL，并去除这些标识。出行日期和酒店位置仍属于个人行程，授权范围不清时先完成可审阅网页，再就发布这份内容询问一次。不要自动公开账号截图或完整证据文件。
- 无托管能力时交付自包含HTML及部署文件，明确缺少线上地址；不让用户重登携程来解决发布问题。

## 验收

实际浏览器检查320、390、768及桌面宽度；日期导航、详情收放、底栏、深链接刷新／返回、无JS回退；不应横向溢出或让底栏挡住末尾内容。检查真实链接、脚本错误、手机截图。无手机微信实机证据就写“浏览器手机尺寸测试通过，微信未实测”。样式更换不能改变订单事实、票价性质和固定日期。
