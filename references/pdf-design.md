# 随身行程 PDF：按天看，按动作读

用于最终攻略的呈现。可用时先读 frontend-design 技能，确定目的地、读者、配色和信息层级；制作与检查遵循当前 PDF 技能。参考圆周旅迹的公开产品逻辑：日期组织、地点顺序、独立交通及住宿卡片。不是复制商标、截图或声称连接该App。

## 默认设计

- 手机阅读优先，窄幅竖版；首页是可点击的日期目录，不做占一页的装饰封面。
- 每日以“日期与重点 → 起终点 → 顺序路线 → 住宿／重要提醒”组织。交通写站点、时间、状态；住宿写连住、床型、早餐及影响入住的限制；景点写停留与预约。不要把整篇攻略段落放进圆角框。
- 建议每张卡片一个动作，标题一行，正文两至三行；一天约三至五张。信息多就拆页，不缩小字体或省略关键限制。轻松日期可合页，避免为了固定页数加空卡片。
- 总览、每日路线、住宿汇总、预算、待办各有用途；不用全篇表格，不加空泛介绍、祝语和重复酒店详情。预算用少量金额分组，逐项明细留在配套Markdown。
- 显著区分已核实、用户确认、历史记录、建议、待订。证据状态必须有文字，不能只用颜色。历史订单绝不能因为采用票据式卡片而变成当前确认。
- 路线连线只表示先后顺序，不画未经核实的地理地图。PDF写入日期、目录和来源链接，但点击能力取决于阅读器；微信内交互需求改用[手机网页](mobile-web.md)。不画假按钮、拖拽手柄或声称实时更新。
- 精简的是叙述，不能删掉机场／车站、日期、关键换乘缓冲、房间容量、退改期限、未确认预约、价格性质。完整核实记录随PDF提供，不把使用所必需的信息全部赶到附录。

示例视觉语言（可依目的地调整）：湖蓝 #087F8C 用于日期与路线，冰白 #F1F7FA 为底，深墨 #183344 为正文，灰蓝 #546C79 为说明，琥珀 #98610B／浅黄 #FFF3D8 表示待核事项。正文用可嵌入中文字体；日期、页码可用窄体数字。标题约26pt、卡片标题15pt、正文11pt。整体留白、连续路线线条与紧凑日期导航共同编码行程顺序，避免不相关装饰。

## 自带卡片导出器

默认用 `scripts/build_cards_pdf.py`，输入为从已核实／明确标记的攻略整理出的JSON。JSON只是本包排版输入，不是圆周旅迹可导入格式。

```bash
python scripts/build_cards_pdf.py outputs/trip-cards.json outputs/攻略.pdf
```

顶层字段：`title`、`eyebrow`、`footer`、`days`、`pages`。`days`为日期导航数组，每项`id`对应页面ID、`label`为短日期；无日程页时可为空。`pages`至少有ID为`overview`的总览页，每页具有：

- `id`：唯一英文标识；`title`：页标题；`kicker`：日期或栏目；`subtitle`：起终点等短说明。
- `day: true`：显示日期导航；`spine: true`：用纵向点线表达卡片顺序。
- `cards`：数组，每卡`title`必填，`label`用于类别与证据状态，`body`为短正文（支持换行），`warn: true`显示待核提醒；`url`可选HTTP(S)来源链接，`target`可选内部页面ID。
- `note`：可选页末短说明。

最小结构示例：

```json
{"title":"旅行随身册","days":[{"id":"day1","label":"09.23"}],"pages":[{"id":"overview","title":"七天行程","cards":[{"title":"09.23 抵达","target":"day1"}]},{"id":"day1","title":"抵达目的地","day":true,"spine":true,"cards":[{"label":"交通 · 待订","title":"机场到酒店","body":"落实接送后再安排当晚活动。"}]}]}
```

使用reportlab；字体选择与旧导出器相同，可用`--font`及`--font-index`指定。字号保持可读，内容超出页面时脚本报错，编辑者必须压缩重复措辞或拆页。保留旧`build_pdf.py`仅作用户明确需要传统长文版时的备选，不能默认把大段Markdown与表格直接灌入最终PDF。

## 必做验收

1. 渲染全部页面，检查中文、长标题、卡片、边距及留白；关键金额及提醒不得跨页丢失。
2. 核对PDF提取文本中的固定日期、交通时刻、预算合计与原始记录，确认精简没有改变事实或状态。
3. 检查日期目录、返回总览和HTTP(S)来源链接实际存在且目标正确；PDF不是可编辑App。
4. 发现一页过密或预算汇总孤立成页，调整内容分组；不要靠减小字体解决。
5. 交付说明实际检查范围。只改版式时，不称订单、价格或场次已重新核实。
