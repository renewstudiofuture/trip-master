# 可迁移的静态网页发布

Trip Master 的网页产物与托管平台分离：生成 index.html 和相对路径 assets/，发布到当前使用者授权的托管空间，再以平台真实返回的网址交付。不是每台电脑自带服务器；不同使用者可用不同平台，同一使用者换电脑也可继续更新原项目。

使用者只安装 Trip Master。不得把 launch-website、Cloudflare/Wrangler 技能或其他发布技能列为必装依赖；环境已有相关工具或技能可以复用，没有则通过官方接口、已安装的命令行工具或平台网页完成。不要为发布默认安装一串扩展，也不要把作者本机的工具路径、账号、项目、域名或凭据带给其他使用者。

## 选择目标，只确认真正缺少的事项

1. 用户指定平台或域名：优先按指定目标发布，先检查权限和是否适合当前静态产物。
2. 该旅行工作目录已有发布记录：核对记录中的项目与当前授权账号，确认确实对应本旅行，再更新原项目。不能列出项目后直接复用第一项，也不覆盖不相关网站。
3. 无记录但当前环境有已授权且适用的托管服务：采用现有能力；若存在多个同等可用目标，按用户既有偏好选择，无法判断时只问一次目标偏好。
4. 没有可用服务：给一个免费静态托管的默认建议，核对当前官方方案后让用户完成必要登录或授权。Cloudflare Pages、GitHub Pages 等只是候选，不是硬编码依赖。用户自有静态服务器也可使用。
5. 暂时无法发布：仍交付完整静态文件包，并给出选定平台的具体上传下一步。不能把本地路径、临时预览或局域网地址称为公开分享网址；不能伪造部署成功。

选择顺序以已有授权和最少操作为先，免费为默认偏好，不默认购买服务或域名。平台费用、公开仓库要求、权限与部署命令在实际发布时按官方文档核验；不把旧版规则当成永久条件。

## 生成与上传

- 用户要求发布或明确委托生成可分享网址即构成该任务的发布授权，沿用同轮已有授权；仅浏览或修改本地预览不等于授权上传。
- 建立专用发布目录：只含已审阅的 index.html 和其引用的公开图片等必要资产。不要直接上传整个旅行工作目录；排除研究缓存、原始截图、账本、个人行程备份、账号配置、订单/证件信息和发布记录。
- 图片使用相对路径，例如 assets/cover.png。页面锚点和图片须同时兼容域名根目录与 GitHub 项目子路径；不得写死本机 file://、绝对磁盘路径、/assets/ 或作者域名。
- 技能生成的是普通静态文件，不要求服务端、数据库或专属部署框架。页面换肤、个人调整和记账在浏览器执行，服务端变化不使它们自动失效。
- 按当前环境官方工具/接口执行上传，认证由平台完成。只在确实缺少权限、身份验证或项目选择时交给用户，不反复要求已完成的登录。
- 获取部署返回的实际 URL；检查 HTTPS、页面内容是否属于本次构建、图片能否在实际部署路径加载。随机预览URL与稳定生产URL应区分，分享默认使用已核验的稳定入口。
- 分享按钮读取当前页面的 location.href，不写死部署域名。若实际预览处于嵌入容器，应核验分享出来的是成品公开URL而不是编辑器地址。
- 最后给出链接和手机打开检查提示。部署成功与用户所在网络可访问是两项验证；微信可达性未测就说明未测。拦截时调查域名/平台访问，不用短链掩盖同一个被拦截目标。

## 每个旅行项目独立记录

成功后在旅行工作目录保存 deployment.json（不放入公开目录、不打包进通用技能）。只记录非敏感字段：provider、project_id 或 repository、production_branch、public_url、发布目录相对路径、trip_id、revision、部署标识及核验时间。无需记录本机用户名和绝对路径。令牌、密码、Cookie、SSH私钥不写入此记录。

更新时从本项目记录恢复目标，并核验当前账号对该项目有权限。换电脑后若仍能访问同一项目，就继续原网址；只有缺少授权时才补认证。换使用者或复制为新旅行时创建该使用者自己的目标，不继承作者账号授权或误用原旅行项目。

## 本地数据的域名边界

主题、账本和个人行程只保存在当前浏览器的当前站点存储中。更新同一网址通常可继续读取；换域名、换设备或不同浏览器不会自动迁移，须导出/导入个人记录。共享同一个网址也不等于共享账本。

当前模板账本及个人行程按 trip_id 隔离，主题为浏览器级偏好。同一域名的不同子路径共享浏览器存储，因此不同旅行必须使用不同 trip_id；同一旅行更新保留 trip_id。发布适配不得为了换平台重置ID或删除个人数据。
