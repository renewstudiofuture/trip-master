# 携程：自动进入订单，最少交互

仅在用户要求查看携程订单或围绕其已订行程规划时使用。遵循当前浏览器工具文档，不硬编码旧DOM选择器，不绕过登录／验证码，不读取cookie、token或隐藏应用状态。

## 已登录的最短路径

1. 先保留用户已说明的登录、浏览器及订单页状态，再使用当前工具已提供的标签信息。信息不足才做一次标签清单读取；优先订单页，其次现有携程页。用户指定浏览器时尊重指定，否则复用已登录携程所在浏览器。清单为空或缺少用户已打开的页面时，先执行下方“会话接续冲突”，不能跳到新建页面。
2. 如果已经是订单中心／详情页，直接读取；若在携程首页或酒店首页，同一标签导航到订单中心 `https://my.ctrip.com/myinfo/all`。这是已知入口，不需要用户手动选择订单界面。若当前页面提供不同的有效“我的订单”链接，使用该可见链接；站点入口变动时不要穷举猜测URL。
3. 导航后观察一次页面状态。显示订单就继续；显示登录页才请用户完成登录；显示验证码才请用户验证。用户完成后直接继续订单读取，不再要求“请打开订单页”。
4. 根据当前可见UI选择“未出行”或适用日期／类型筛选。读取与本次旅行相关的订单列表和分页信息，再打开缺少关键字段的有效订单详情。
5. 如果“未出行”没有结果，检查筛选、日期、分页和订单类别；必要时查全部订单中的相关日期。不能把空列表当作用户没有任何预订，也不能无限遍历历史订单。

仅当用户未报告已有携程页面、且工具正常返回的清单确实没有携程标签时，才在适用浏览器打开订单中心。实际显示登录页才请求登录；不要从空清单推断登录状态。不要同时打开四个平台，不切换到另一个未登录浏览器来重复登录流程。

## 会话接续冲突：用户已打开，工具却看不到

触发条件：用户已说明携程登录完成或订单页已打开，但工具返回空清单、目标标签缺失、句柄失效或无法读取；工具可见状态与用户报告不一致。

分别记录“用户报告已登录／已打开”“工具是否识别目标标签”“本轮是否读到订单内容”。前者保留为用户确认，后两者不能由前者推定成功；工具未识别也不能反过来否定用户报告。环境附带的URL可以帮助定位，但不代表成功读取或用户指定了浏览器。

1. 检查已有信息中的浏览器来源、浏览器ID、标签ID、URL与标题是否对应同一页面，先排除连接到另一个浏览器或会话。只用工具公开返回的信息及当前文档支持的接口，不读取浏览器配置、凭据或隐藏状态。
2. 给该故障最多一次有依据的恢复机会：若有当前有效目标ID，按工具文档重新获取既有标签；若清单可能失效，重新发现可用浏览器／标签。首次清单读取不算恢复，之后的清单刷新或重新获取算这一次机会；无可用恢复机制时直接停止。ID失效后不得猜新ID或重复使用旧ID。
3. 恢复后发现原订单页，就直接读取；发现用户原有携程首页，才在同一标签进入订单中心。标题或URL可见仅算“已定位”，拿到相关可见订单字段才算“已读取”。
4. 仍找不到或仍无法读取时，停止账户路径。此分支不新建标签、不刷新或关闭用户原页、不注销、不切换浏览器重登，也不要求用户再点击“我的订单”。只有用户明确说明原页已关闭或要求新开时才另行导航。

说明应当是：“你已登录并打开订单页，但当前工具未能接续到该页面；尚未读取订单内容。”只有实际看见登录页、验证码或明确错误，才陈述相应原因；单凭超时不归因为账户、风控、网页加载或底层工具故障。

继续独立的公开研究；历史订单明确标为历史、用户确认项保留为用户确认。仅在关键字段缺失且阻断下一步时，请用户补最小字段摘要；如果有证据表明一个具体的连接／共享动作能解决，再说明该动作及作用，不让用户重做已完成的登录和导航。连接恢复或用户提供新证据后，只补缺口。

验收分别记录：目标页面接续、页面导航（若需要）、有效订单读取。接续失败即该项失败，不能因少调用或页面标题可见就判账户读取通过。“已登录首页”和“已打开订单详情”的分支未实际运行时标为未覆盖。

## 一次读全必要字段

交通：日期、状态、航班／车次、出发到达机场车站、航站楼、时刻、人数、总额与付款状态。行李等会影响选择时再展开，不为无关细节反复读取同一页面。

酒店：名称、地址、入住退房、房间数、床型、实际入住容量、早餐、总额、付款时间、免费取消截止和显著入住限制。对新住宿的公开候选研究退出账户路径，改用搜索工具。

门票：若订单中有，记录日期、场次、人数和含车项目；若用户明确已订但未读到，标“用户确认”，不重复购买或改日期。

阅读范围限于任务需要，不提取无关旅客信息。分享文档不包含姓名、证件、订单号、签名链接。需要来源时用“携程订单中心，核实日期”及普通入口，不公开带签名详情URL。

## 减少慢调用

- 复用有效句柄和标签，不每轮重新开页。平台清理导致失效时才重新获取。
- 一次快照读到的内容保存到当前任务，页面没变化就从缓存提取。`snapshot().slice(...)`只缩短返回内容，不能减少快照生成成本，不把它当提速手段。
- 初次观察后，工具支持时只读已定位的相关可见区域。不得使用未获文档支持的API或隐藏页面数据取代UI。
- 合并已经明确、无需中间观察的简单步骤；涉及新联想项、新标签或页面条件的步骤先观察再决定，不盲目连点。
- 点击详情通常会开新标签，确认一次标签变化并认领新页，不重复点击。

## 超时恢复与请求协助

若同时满足“会话接续冲突”，优先执行该分支；两处恢复共用一次机会，不能先做一轮冲突恢复，再重新计算超时重试次数。

首次超时：先轻量检查目标页面或标签是否已变化；操作可能已经生效，不能直接重做。若已生效，继续读取；若未生效且有依据，重新获取句柄或恢复连接一次。

同一故障连续两次、恢复后仍无新证据：停止当前失败路径，不靠多开标签、切浏览器、反复截图延长等待。说明“携程订单读取连接异常”，继续公开研究。若订单是下一步不可缺的输入，优先请用户提供日期、时间、酒店等最小摘要；用户自愿提供截图也可读取。只有观察到特定导航操作确实无法执行、且手动操作能解决时，才请求那一个动作，不能笼统要求用户重新登录或自己找订单页。

不得把未完成账户核实说成已完成。连接恢复或用户提供新证据后，只补缺少字段。
