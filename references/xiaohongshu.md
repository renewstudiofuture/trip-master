# 小红书：内置源码，先筛选后读取

本 Skill 包含 scripts/xhs-extract.js，小红书卡片提取部分改编自 AutoCLI/OpenCLI Apache-2.0 源码，许可和署名在 vendor/。不安装 AutoCLI Skill、主程序、后台服务或 AutoCLI 专用扩展；已有测试安装不是依赖，也不自动卸载用户已装软件。

## 依赖边界

需要宿主 AI 环境已有的浏览器控制／读取能力及用户小红书登录态。优先使用该环境支持的工具，不另装浏览器插件、爬虫、MCP 或运行时。没有浏览器能力时明确说明本环境无法完成站内排序，可接收用户分享的已筛选内容；不能声称零环境依赖。公共开放、价格、预约信息仍使用搜索工具核实。

## 固定顺序

1. 复用小红书现有标签页或打开一个搜索页，首轮一个“目的地＋月份＋路线”查询。别先跑普通搜索提取再本地排序。
2. 检查实际页面。仅在看到登录墙时交给用户扫码：保留同一标签页并用交互弹窗请用户选“已登录，继续搜索”或“未看到二维码”。等明确回复再恢复，等待期间不刷新、不反复检测。不索要验证码、密码或 Cookie。
3. 展开“筛选”，选择“排序依据 → 最多点赞”，不改变其他筛选条件。读取最新状态确认该选项已选中，等待结果刷新。不能仅凭点击成功或“已筛选”三个字断言最多点赞已生效。
4. 保存当前查询绑定的短证据：`{label:"最多点赞", query, selected:true, kind:"screenshot"|"accessibility"|"dom", observedAt:ISO时间, resultsSettled:true}`。字段必须来自本次真实观察。结果刷新中的暂时空态不立即当无结果；一次后续状态检查确认。无法确认排序就停止，不降级为本地排序冒充完成。
5. 有受支持的只读页面执行接口时，把 scripts/xhs-extract.js 中的函数传入页面读取，调用 `tripMasterXhsExtract({query, sortEvidence, limit:20})`。遵循宿主工具允许的执行方式，不绕过其限制。仅当现场 DOM 支持源码所用选择器时执行；页面变化先检查再改。
6. 若工具只能读取辅助功能文本或截图，则直接读同一已筛选页面的卡片，不安装额外组件；保持页面顺序、记录标题/作者/点赞/链接，并标注人工式工具读取。这与 JS 提取是同一流程的两种读取方式。
7. 保持站内结果顺序，以笔记 ID 去重，必要时少量滚动读取下一屏；先取得约20条，精读其中相关的3–5篇。查询改变或重新导航后必须重新确认站内排序，不能复用旧筛选证据。不得调用原 AutoCLI search 重新打开默认综合页。

## 结果与质量

缺点赞留未知，不默认为0；1.2万等为近似值。源码转换单位仅用于展示与核对，不用本地排序替代站内筛选。只称“此查询站内最多点赞结果”，不声称全站绝对热榜。广告、过时季节与不适合预算的内容单独判断；热度不是事实可信度。

作者与日期混在一起时保留 author_date_raw，不猜拆分年份。卡片不等于正文；实际读取正文／路线图后才引用路线。签名链接 detail_url_private 只在本地用于继续读取，公开攻略只输出无签名 url，不发布原始研究文件、账号信息。

研究缓存沿用 research-cache.json，键包含查询、排序、季节、采集时间；旧的综合排序缓存不可当最多点赞缓存。保存紧凑字段，五模块共用。不要整批下载图片或视频。用户交通住宿继续仅由用户提供。

## 故障边界与验证记录

用户说已打开／已登录但工具超时时，重新列举标签页一次；还读不到就报告工具连接故障，不要求反复扫码。同一故障一次诊断加一次有针对性的恢复后停止，保留现场与下一步。浏览器标签读取超时但原生应用辅助功能可读时，可复用现有原生工具；不要重开页面或增加扩展。
